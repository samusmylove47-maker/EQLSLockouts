# Evidence ledger

Every line shape the module parses, where it came from, and what we searched for
and did not find. Figures are read out of `analysis/findings.json`, regenerated by
`node analysis/derive.js`.

**Corpus.** 15 log files, 433,914,867 bytes, 5,253,948 lines, characters Avenrae
and Shara on server rivervale, 04–18 Aug 2026. Only 11 files hold unique content:
`eqlog_Shara_rivervale3.txt` and `eqlog_Shara_rivervale5.txt` are byte-identical
across the two directories, `eqlog_Shara_rivervale4.txt` is a byte-prefix of
`rivervale5.txt`, and `rivervale5.txt` is a byte-prefix of
`eqlog_Shara_rivervale_2026-08-14b.txt`. **Raw grep counts over-count events by
about 3×.** Everything below is de-duplicated.

**Encoding: UTF-8.** Measured, not assumed. Exactly 9 bytes ≥ 0x80 exist in the
whole corpus; all 9 are `EF BF BD` (U+FFFD REPLACEMENT CHARACTER), a well-formed
UTF-8 three-byte sequence. `iconv -f UTF-8 -t UTF-8` exits 0 on all 15 files. The
cp1252 signature bytes `0x92 0x93 0x94 0x96 0xA0 0x85 0xE9` return **0** matching
lines. Line endings are **LF**, not CRLF.

*Second layer, which is not settled:* U+FFFD is the fossil of a decode that
already lost a byte. So "UTF-8 is the right decoder for the bytes on disk" is
settled; "the client originally emitted UTF-8" is not, and cannot be settled from
a corpus whose only non-ASCII content is the replacement character itself. One
log line containing a real accented character or curly quote would close it.

**Clock.** Log stamps carry no timezone. The machine reads `Eastern Standard
Time` (Windows tz id; UTC−05:00 base, DST active in August ⇒ UTC−04:00), read off
the OS on 21 Aug 2026. Pacific is UTC−07:00 on the same dates; both zones are in
DST, so the offset is exactly 3 hours.

## Difficulty grammar — derived

Read out of the client's own instance-invite line across 27 distinct instance
names, no exceptions, no conflicts:

| index | label |
|---|---|
| 0 | Normal |
| 1 | Awakened |
| 2 | Adaptive |
| 3 | Fused |
| 4 | Refined |

Grammar: `<Zone>[ - Group] <index> (<Label>)`. A bare zone name is the **open
world**. `- Group` marks the group instance; its absence on an instanced name
marks the raid instance. `- Group` also occurs **with no index and no label** (6
occurrences, 2 zones) — that is still an instance with difficulty **not
recorded**, and must never be defaulted to 0.

## Clearances — the exact strings searched

Each of these is "we searched for this and did not find it", not "it does not
exist". All searches are over the 15 files above unless stated.

- `grep -F " - Solo"` over the 68 distinct zone strings → **0**. The shape is
  still parsed; zero occurrences is not zero forever.
- `grep -F "outstanding replay"` → **0**. `/dzlisttimers` has never been run.
- `grep -F "recently experienced"` → **0**. `grep -F "recently played here"` → **0**.
- `grep -F "You do not have a lockout"` → **0**.
- `grep -i "lockout"` → 104 hits, `grep -i "locked out"` → 32 hits (raw, so
  inflated by file duplication). **Every one is player chat. Filtering out the
  chat verbs leaves zero system lines.**
- Only **two** system line shapes containing the word "task" exist in the whole
  corpus: `You have been assigned the task '...'.` and `Your task '...' has been
  updated.` There is **no** completion line, removal line, expiry line, failure
  line, or timer line of any kind.

## The client string table

`<install>/eqstr_us.txt` (454,972 bytes) and `<install>/eqlsstr_us.txt` (19,070
bytes, EQL-specific) are on disk at
`C:\Users\Public\Daybreak Game Company\Installed Games\EverQuest Legends`.

`eqstr_us.txt` carries the full DZ/expedition command family, including:

> `3536 Usage: /dzListTimers    - This command will list any outstanding replay
> timers you have for all expeditions.  This is the amount of time you must wait
> before being allowed to enter another instance of that zone.`
>
> `3501 You cannot create this expedition for another %1d:%2h:%3m:%4s since you have recently played here.`
>
> `5089 %1 has recently experienced %2 in %3.  They must wait another %4d:%5h:%6m:%7s until they can experience it again.`
>
> `8338 You are not allowed to loot the item: %1. You do not have a lockout timer for this event that matches the current instance.`
>
> `5043 One or more raid members has an event lockout for this instance: %1Click yes to apply the above lockout(s) and begin the expedition.`

**A string being in the table does not mean the server implements it.** The table
is not EQL-customised — `voidling`, `Void-Touched`, and `Potential of the Void`
all return **0** in both `eqstr_us.txt` and `dbstr_us.txt`, so it is inherited
Daybreak content. **But three strings from that same expedition block fire
verbatim in our own logs** (3527 × 83, 3522 × 1, 3513 × 1), and 3513 is a
*permission error*, which means a `/dz` command was typed and the server
answered. The family is live. Whether `/dzlisttimers` specifically returns
anything is one command away and is step 1 of the capture protocol.
